# Установка Podkop
Пакет работает на всех архитектурах.
Будет точно работать только на OpenWrt 23.05.

Нужен dnsmasq-full. В автоматическом режиме ставится сам. Вручную надо поставить [самостоятельно](https://github.com/itdoginfo/podkop/blob/952dd6215a2a83d65937cf9e33534c42809091ed/install.sh#L20).

## Автоматическая (одной командой)
```
sh <(wget -O - https://raw.githubusercontent.com/aiserrock/podkop/main/install.sh)
```

Команда скачивает `install.sh` из этого форка, который ставит последний релиз
`podkop_*.ipk` + `luci-app-podkop_*.ipk` из
[releases этого репозитория](https://github.com/aiserrock/podkop/releases/latest),
доставит зависимости (`dnsmasq-full`) и предложит выбрать туннель.

> Язык интерфейса по умолчанию — **английский**. Русский перевод ставится
> только если ответить `y` на отдельный вопрос (Enter / `n` = английский).

> В конце установки скрипт предложит **доустановить sing-box-extended** (больше
> протоколов/возможностей) через установщик
> [EikeiDev/OpenWRT-sing-box-extended](https://github.com/EikeiDev/OpenWRT-sing-box-extended).
> По умолчанию — нет (остаётся обычный `sing-box`). При согласии запускается их
> установщик, где вы сами выбираете версию.

> Для установки одной командой в репозитории `aiserrock/podkop` должен быть
> хотя бы один релиз. Релиз собирается автоматически при пуше тега (см.
> «Сборка релиза» ниже). Если релизов ещё нет — используйте установку из
> исходников.

Скрипт также предложит выбрать, какой туннель будет использоваться. Для выбранного туннеля будут установлены нужные пакеты, а для Wireguard и AmneziaWG также будет предложена автоматическая настройка - прямо в консоли скрипт запросит данные конфига. Для AmneziaWG можно также выбрать вариант с использованием конфига обычного Wireguard и автоматической обфускацией до AmneziaWG.

Для AmneziaWG скрипт проверяет наличие пакетов под вашу платформу в [стороннем репозитории](https://github.com/Slava-Shchipunov/awg-openwrt/releases), так как в официальном репозитории OpenWRT они отсутствуют, и автоматически их устанавливает.

## Вручную

Скачать пакеты `podkop_*.ipk` и `luci-app-podkop_*.ipk` из релиза. `opkg install` сначала первый, потом второй.

## Режимы

### Proxy
Для VLESS и Shadowsocks. Другие протоколы тоже будут, кидайте в чат примеры строк без чувствительных данных.
Для использования этого режима нужен sing-box:
```
opkg update && opkg install sing-box
```

В этом режиме просто копируйте строку в **Proxy String** и из неё автоматически настроится sing-box.

### VPN
Здесь у вас должен быть уже настроен WG/OpenVPN/OpenConnect etc, создана Zone и Forwarding.

Просто выбрать интерфейс из списка.

## Настройка доменов и подсетей
**Domain list enable** - Включить общий список.

**Delist domains from main list enable** - Выключение заданных доменов из общего списка. Задавать списком.

**Subnets list enable** - Включить подсети из общего списка, выбрать из предложенных.

**Custom domains enable** - Добавить свои домены. Задавать списком.

**Custom subnets enable** - Добавить подсети или IP-адреса. Для подсетей задать маску.

# Новое в этом форке

## Third config (третья цепочка)
Вкладка **Third Config** — третья независимая цепочка маршрутизации, полный
аналог Second Config. Свой туннель/прокси, свои домены и подсети. Технически:
порт 1604, fwmark 0x107, таблица маршрутизации `podkop3`, nft-сеты
`podkop3_domains` / `podkop3_subnets`. По умолчанию выключена (`third_enable 0`)
— при выключенной галочке поведение идентично оригиналу.

## Download lists via main tunnel
Галочка **Download lists via main tunnel** (вкладка Additional Settings, только
proxy-режим main). Когда включена, списки доменов/подсетей качаются через
основной туннель (main), а не через прямой канал роутера — нужно, если GitHub
заблокирован провайдером или режется DPI.

Как это работает:
- поднимается локальный вход в sing-box `127.0.0.1:2081` (только loopback,
  наружу не виден), маршрутизированный явно в outbound `main`;
- загрузки идут через `curl --socks5 127.0.0.1:2081`; при сбое туннеля —
  3 попытки с нарастающей задержкой, и только потом fallback на прямой канал;
- вход поднимается перед каждым `list_update`, поэтому списки качаются через
  туннель **и при перезагрузке роутера, и при суточном обновлении по крону**.

## Устойчивость старта к недоступному GitHub
Раньше при недоступном GitHub загрузка списков крутилась в бесконечном цикле
прямо внутри `start_service`. Если туннель лежал (а из РФ без туннеля GitHub
обычно недоступен), podkop зависал посреди старта: маршрутизация и правила
после этого шага не применялись, и сеть сама не поднималась. Списки при этом
лежали в `/tmp`, то есть после перезагрузки кэша не было вовсе — получался
замкнутый круг «для туннеля нужны списки, для списков нужен туннель».

Что сделано:
- **дедлайн на список** (`LIST_FETCH_DEADLINE`, 25 с) и **общий бюджет на весь
  старт** (`LIST_BUDGET_TOTAL`, 45 с) — время вышло, старт идёт дальше;
- **кэш списков на флеше** `/etc/podkop/cache/` — переживает перезагрузку,
  маршрутизация поднимается вообще без сети;
- **фоновая дозагрузка** `/usr/libexec/podkop-list-retry` — ждёт возврата связи,
  сам вызывает `list_update` и обновляет списки; плюс хук
  `/etc/hotplug.d/iface/51-podkop-retry` срабатывает сразу при `ifup` на wan.

Замер на роутере (Xiaomi AX3000T, GitHub заблокирован на время теста):
рестарт **не завершался вовсе** → стал **69 с**, после возврата сети списки
подтягиваются сами примерно за полторы минуты. Обычный рестарт — 21 с.

## Backup / Restore конфигурации
Во вкладке Diagnostics:
- **Backup** — скачивает текущий `/etc/config/podkop` файлом в браузер.
- **Restore** — загрузка файла бэкапа: конфиг валидируется (структура + UCI-
  синтаксис в изолированной проверке), текущий сохраняется в
  `/etc/config/podkop.bak-<дата>`, затем применяется новый и podkop
  перезапускается.

## Уровень логов (debug)
Опция **Log Level** (Additional Settings): `normal` (как раньше) или `debug`.
В режиме debug подробные логи каждого шага (маршрутизация, sing-box, загрузка
списков с retry) пишутся в системный журнал и в `/tmp/podkop.log`. Кнопка
**View Debug Log** в Diagnostics показывает полный лог. Секреты (proxy-строки,
uuid, пароли) в логи не попадают.

## Пример: 3 сервера с точечной маршрутизацией
Сценарий — основной сервер в Нидерландах, плюс отдельные маршруты в Англию и на
домашний NAS в России:

| Цепочка | Сервер | Что туда идёт |
|---------|--------|---------------|
| **main** (Config) | Нидерланды 🇳🇱 | основная точечная маршрутизация (общий список доменов + свои домены) |
| **second** (Second Config) | Англия 🇬🇧 | `10.10.10.10` (Custom subnets) + YouTube (Service list) |
| **third** (Third Config) | Россия, NAS 🇷🇺 | `10.20.30.0/24` и `192.168.1.0/24` (Custom subnets) |

Настройка:
1. **main** — Proxy, строка VLESS сервера в Нидерландах; включить Domain list
   (например `ru_inside`) и свои домены.
2. **Second Config** — включить, Proxy, строка VLESS Англии; Service list →
   Youtube; Custom subnets → `10.10.10.10`.
3. **Third Config** — включить, Proxy (или VPN, если NAS за WG-интерфейсом),
   данные сервера в России; Custom subnets → `10.20.30.0/24`, `192.168.1.0/24`.
4. В Additional Settings включить **Download lists via main tunnel** — общий
   список доменов и YouTube-список будут скачиваться через Нидерланды.

`10.10.10.10` и подсети для NAS — статичные адреса, они не скачиваются (сразу
кладутся в nft), поэтому блокировка GitHub на них не влияет. Скачиваются только
домены main и YouTube-список — оба через туннель main.

# Разработка
Есть два варианта:
- Просто поставить пакет на роутер или виртуалку и прям редактировать через SFTP (opkg install openssh-sftp-server)
- SDK, чтоб собирать пакеты

Для сборки пакетов нужен SDK, один из вариантов скачать прям файл и разархивировать
https://downloads.openwrt.org/releases/23.05.5/targets/x86/64/
Нужен файл с SDK в имени

```
wget https://downloads.openwrt.org/releases/23.05.5/targets/x86/64/openwrt-sdk-23.05.5-x86-64_gcc-12.3.0_musl.Linux-x86_64.tar.xz
tar xf openwrt-sdk-23.05.5-x86-64_gcc-12.3.0_musl.Linux-x86_64.tar.xz
mv openwrt-sdk-23.05.5-x86-64_gcc-12.3.0_musl.Linux-x86_64 SDK
```
Последнее для удобства.

Создаём директорию для пакета
```
mkdir package/utilites
```

Симлинк из репозитория
```
ln -s ~/podkop/podkop package/utilites/podkop
ln -s ~/podkop/luci-app-podkop package/luci-app-podkop
```

В первый раз для сборки luci-app необходимо обновить пакеты
```
./scripts/feeds update -a
```

Для make можно добавить флаг -j N, где N - количество ядер для сборки. Первый раз пройдёт быстрее.

При первом make выводится менюшка, можно просто save, exit и всё. Первый раз долго грузит зависимости.

Сборка пакета. Сами пакеты собираются быстро.
```
make package/podkop/{clean,compile} V=s
```

Также для luci
```
make package/luci-app-podkop/{clean,compile} V=s
```

.ipk лежат в `bin/packages/x86_64/base/`
